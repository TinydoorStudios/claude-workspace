# RULES — the hard rules for every show build, in one place

*The single canonical list. Every other document (CLAUDE.md, NEW-SHOW.md, ROUTING.md, the
show-deep-build skill, the KB pipeline specs) points here by number and does not restate.
Change a rule here, nowhere else. History of changes: git log on this file.*

## A. Console and paperwork format

- **R1** Console default is the DiGiCo Q225 (Memo, FSQ) or Behringer Wing (secondary venues). Never CL3 or M32 output unless Brian names that desk.
- **R2** Q225 EQ = HPF + LPF + 4 bands. Band numbers match the console: **B1 = LF … B4 = HF.** Display and document order high→low: `HPF · LPF · B4 · B3 · B2 · B1`. Any band Shelf or Bell; any Bell may be Dynamic; a low shelf is B1 in shelf mode. No separate low-shelf control.
- **R3** Gain ±18 dB, **Q 0.3–10**, whole-dB gains only (never a half dB; round the cut deeper).
- **R4** The FOH `.md` format is locked (`## Ch N | NAME | MIC`, `HPF: | LPF:`, `B4..B1` lines, `FLAT` for a bypassed band, optional `DEQ:`, `COMP:`, `GATE:`). Console name ≤ 12 characters. `md_lint.py` enforces it and the patcher aborts on lint errors.
- **R5** `spec.json` is the source of truth for a show. A late revision edits the spec, bumps `rev`, and regenerates the `.md`, xlsx, PDFs and `.ses`. If the `.md` on disk was edited after the last build, `build_packet.py` stops and reconciles the differences with Brian channel by channel; it never silently overwrites either side.
- **R6** All show PDFs are reportlab, generated by `build_packet.py` and `make_mobile_patch_sheet.py`. No HTML stage. Default deliverable for anything else is PDF, Calibri body.
- **R7** The packet is: FOH `.md` · Input List `.xlsx` · Show Packet PDF · EQ Rationale PDF · MASTER PDF (with quick-links page) · `.ses` · `spec.json`, plus the phone patch sheet. Stage plots are band-provided, never generated; file as `<Show> - Stage Plot.pdf` and the MASTER picks it up.

## B. EQ philosophy

- **R8** Subtractive first. Cuts before boosts on every source.
- **R9** **Vocals are cuts only, every genre** (feedback control, not taste). A vocal boost is a build error unless the band carries `"approved": true` after Brian's explicit OK.
- **R10** No high-shelf band unless Brian asks.
- **R11** Typical indoor: cuts −4 to −7 dB, tight Q (1.5–2.0); non-vocal boosts +3 to +6 dB.
- **R12** **Outdoor (FSQ, WP, ESP, CSP, ZP, IA): cuts one step deeper** — −6 to −9 typical, up to −10 on mud or box. Torn between two depths, take the deeper. HPF higher, decisive.
- **R13** Genre modifiers: classical = minimal, cuts only; acoustic/folk = conservative, the 1.5–2 kHz piezo quack is the primary cut; Celtic = 5 ms+ gate attack, never gate sustained notes; everything else aggressive by default.
- **R14** Memo standing waves **63 / 125 / 200 / 250–315 Hz**: cuts favoured, boosts there suspect; bodhrán and kick are the highest-risk channels; DEQ where a static cut won't hold; RT60 ~1.6 s.
- **R15** The capsule-voicing gate: never boost into a peak the capsule already bakes in (trim it instead); never deep-cut a zone the capsule already scoops. Every boost cites the capsule fact that clears it.
- **R16** Two-mic sources (kick in/out, 57/121, DI + cab) are one signal with lane ownership: no stacked boosts top or bottom, low-mids backed off on the complement mic, polarity/mono check planned, both channels' `mic_notes` say who owns what.
- **R17** Sections (horns, BVs, twin guitars) are slotted in the band values, each channel's lane named in its `eq_summary`. Three near-identical curves under a "slot the section" note is a failed build.
- **R18** Dynamics are reasoned with numbers (attack/release ranges, ratio, what must survive a gate) and DOCUMENTED as `COMP:` / `GATE:` lines in the `.md`. They are **never patched into the `.ses`** (Brian pulled the Mustard writer 2026-07-16). Mustard colour comes from the reasoning: Blue = Neve, Red = API/VCA, Green = FET, Purple = Optical, Silver = Levelling.
- **R19** Reverbs are required every show, FSQ included: three complementary vocal options, one or two instrument, one general when warranted. Seventh Heaven Pro preset names verbatim from the reverb KB, every setting anchored "(factory)" or "(from X factory)", selection justified by this band's material. Opt out only with `"no_reverb": true` on Brian's say-so.

## C. Research discipline

- **R20** Genre is verified with named evidence before any research runs. Split or hybrid evidence = ask Brian immediately.
- **R21** Artist research runs fresh every show, never cached. Live footage and setlists outrank press copy. The artist profile refines and outranks the generic genre read.
- **R22** Per-input order of importance and process: **instrument (+ its notated equipment) → mic → genre → venue.** The venue is applied last, as a constraint filter that trims and vetoes but never rewrites the foundation.
- **R23** The research floor: every unique instrument × mic unit gets its own fresh web pass with at least one quantitative capsule fact (a frequency and a dB value) from a named external source. **The KB is for longevity, not research** — it cross-checks and resolves, never substitutes. No familiar-mic exemption. Notated equipment (amp/cab, drum sizes, strings, pickups) carries the same floor.
- **R24** Reconcile web vs KB with exactly one word per unit — AGREE / DISAGREE / THIN — written before any numbers. DISAGREE or THIN is a stop-and-ask with three options: research, KB, or research plus a KB update.
- **R25** Every unit carries a five-layer TRACE (base · equip · genre · artist · venue), each layer a value or an explicit "no change", and the trace must match the channel's actual band values.
- **R26** Outdoor shows: weather is fetched for the show window (Open-Meteo, Tempest) and quoted with numbers and source. Seasonal assumptions are banned. Saturated air (RH ≥ ~90%) inverts the HF call: no HF boosts, trim baked peaks.
- **R27** Research is visible — real searches as tool calls Brian can see — and final EQ numbers never appear in the same message as the research that justifies them.
- **R28** An unsure answer is worse than a pause. Unknown artist, mic, instrument, genre, venue or value = stop and ask. Never paper a gap with a confident guess. Mine every channel note; never drop one on the floor.

## D. Mics, patching, faders

- **R29** Ribbon mics (R-121, R-10, R88): **NO 48V**, flagged red, every time. Ribbon + phantom in a spec is a build error. The passive R88 mk2 never sees phantom.
- **R30** Artist-provided gear is flagged ⚑ TOUR, amber, "confirm at load-in", and is never swapped or re-specified.
- **R31** Mic identities: any "87" is the Warm Audio WA-87 (no Neumann U87 in the kit); any "421" is the vintage MD 421-U Silver Tail; a bare "408" is the EV N/D 408 (the Lauten LS-408 is "the Lauten"). `mic-library.md` is authoritative on what Brian owns.
- **R32** The locker fork: every mic'd input is checked against the locker for one owned, unassigned alternative with a concrete win. DI and XLR line-feed inputs, TOUR mics and the fixed Memo crowd rig are exempt. A fork carries exactly three sentences (the win with a number · what it changes · the honest cost) and Brian decides; an unanswered fork blocks the build.
- **R33** House wireless faders: **FSQ 33–36, Memo 41–44** = Wireless 1–4. A channel whose mic names a unit (`Wireless 2`, `W58 2`, `WL2`, `W2`) mults the receiver: both rows listed, same source port, ride the digital trim on the mult. A bare `W58` with no unit number is a stop-and-ask.
- **R34** FSQ fader 10 is the SNARE PL8 reverb return, never an input; the overhead pair is STEREO on fader 9, never split 9/10. Enforced in `build_packet.py` and the FSQ patcher.
- **R35** Memo crowd rig (Line Audio OM1 flown, Deity S2 under the PA, Line Audio CM4 balcony ORTF) is always patched, channel numbers blank, EQ fixed from the KB — never re-derived.
- **R36** Broadcast shows use underheads/underhat, not overheads; cymbal mic choice is read from the input list every show, never carried over.
- **R37** Local inputs are written "Local 1", never "L1"; AES inputs "AES-1". Stands come from the physical mic (an e609 has no clip; a cab mic takes a Short stand).

## E. Process and gates

- **R38** Every new show runs the show-deep-build skill; Brian never has to say "deep think". Only an artist name? Ask for the input list. Never guess a mic from an instrument.
- **R39** Questions are asked **one at a time** with an interactive prompt, recommended option first, locker forks first in the sequence. Never a batched list. Carried flags from a prior rev count as questions.
- **R40** The constraint card: at the start of a build, write these rules in your own words; re-read before the question round and before writing `spec.json`, and say so. Run the pre-commit audit (`references/pre-commit-audit.md`) with evidence quoted before the spec is written.
- **R41** The `.ses` build must print `bytes changed outside mic'd blocks: 0 PASS`, `do-not-write tags modified: 0 PASS`, `readback: PASS`, name×20 on every fader, and an identical file size. Any `!!` or FAIL = not delivered. Run the venue patcher directly; never copy it into the show folder; never edit a template.
- **R42** Console verification is **not** a gate. Brian's explicit go ("SEND IT", "push it") is the only publish gate. A `verified` stamp is informational.
- **R43** Show state lives in `show.status.json` (scaffolded → packet_built → ses_built → verified → published → harvested) with `rev`, file hashes and the canonical **show key** `<venue>-<YYYY-MM-DD>-<slug(artist)>` shared with the band advance database (`_shared/advance_bridge.py` stamps it; the Show Status Log's Packet / .ses / Wiki columns read it back). Read it; never infer state from folder recency.
- **R44** Publishing writes the show's KB write-backs and reconciliation lines to `_learning/PENDING.md`; the next build opens by clearing that queue with Brian one item at a time. Never write the live wiki silently.
- **R45** No narration of work in progress. Research output, the question round and the pre-commit audit are deliverables, not narration.
- **R46** Writing: warm, direct, specific, no AI tells (`about-me/writing-rules.md`). Prose over bullets in conversation; tables for technical data.
- **R47** The workspace is one git branch, `main`. A session that finds another branch checked out stops and says so before any show work.
