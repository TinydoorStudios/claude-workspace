## How the auto-sync works (so you don't break it)

Chain: **local files → GitHub → Wiki.js (pull)**

1. **Mac push:** launchd agent `com.tinydoor.kb-gitpush` watches the local `Wiki/` dir and runs `~/.claude/scripts/kb-git-push.sh` on any change (commit + push to GitHub), plus a 300s fallback. Log: `~/.claude/logs/kb-git-push.log`.
2. **Wiki.js pull:** Git storage target, **pull mode**, interval `PT5M`. GitHub is the source of truth.
3. Net latency: a local edit appears on the wiki within ~5 min.

**Consequence — edit locally, NOT in the wiki web UI.** Pull mode overwrites wiki-side edits on the next sync. If the next adjustment is "let me edit in the browser too," switch the storage target to **sync** mode (bidirectional) — but warn that it can create git merge conflicts against the Mac auto-push, so pick one primary editing surface.

To force an immediate sync instead of waiting: GraphQL mutation `storage{executeAction(handler:"sync",targetKey:"git")}` against the container IP.

## Gotchas already hit (don't rediscover these)

1. **Cloudflare 403s admin API POSTs.** GraphQL mutations through `kb.tinydoorstudios.com` get blocked. Always run admin/API scripts against **http://192.168.0.126:3000/graphql** (LAN/tailnet). Public GETs (reading pages) are fine through the URL.
2. **Wiki.js `storage.updateTargets` config format.** Each config value must be JSON `{"v": <value>}` — the key is **`v`**, not `value`. Wrong key silently stores `null` and corrupts the whole `storage{targets}` query until re-saved correctly. (Resolver: `server/graph/resolvers/storage.js`.)
3. **CT had no DNS resolver on creation** — fixed (`pct set 101 --nameserver 1.1.1.1` + `/etc/resolv.conf`). If you clone/rebuild the CT, set DNS before apt.
4. **The cloudflared tunnel (b1e6581d) is dashboard/remote-managed**, so editing the local `config.yml` on the n8n VM does nothing. Ingress changes go through the Cloudflare API (token decodes from the ARGO TUNNEL TOKEN block in `/etc/cloudflared/cert.pem`, account `fbeee704…`). The `kb` ingress is already added.
5. **Shell-mangled passwords:** the original admin pass had a `!` that zsh history-expansion corrupted in transit. Avoid `!`/`$`/backticks in passwords passed through ssh; reset DB password via `docker exec wikijs-wiki-1 node -e "...bcryptjs.hashSync(...)"` → `UPDATE users SET password=...`.
