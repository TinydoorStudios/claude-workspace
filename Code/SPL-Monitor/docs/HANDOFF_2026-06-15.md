## 4. Research recap (full detail in the comparison PDF)

- **C−A at FOH is a diagnostic, not a limit:** ~0–3 dB = mids/highs, ~6–12 dB = normal
  full-range music, **>~15 dB = bass-dominant** (the watch line).
- **Off-site consensus (UK / Europe):** `LCeq ≤ LAeq + 20 dB`, hard cap **90 dB LCeq** at the
  nearest noise-sensitive property.
- **Paired venue limits:** Hollywood Bowl 95 dBA / 108 dBC (+13); France 102 / 118 (+16).
- **Red Rocks (the model that fits FSQ):** 108 dBA 1-min (→~105 late); 123 dB any-band Leq
  1-min; **"dB1" 25–80 Hz at 125 dB, 1-min, time-gated**; measured at FOH, limits derived to
  correlate with off-site impact; 3-strikes → $10k; per-second logs tuned annually.
- **Verdict:** adopt Red Rocks' *structure* (isolated sub band + night tiers + FOH→property-
  line mapping + log-then-set + 3-strikes), **scaled to FSQ's ~75 dBA property-line reality** —
  the absolute amphitheater numbers do not transfer.

## 5. PLAN — add the 63 Hz octave sub-band metric

### 5.1 Decisions locked
- **Band:** **63 Hz octave (~44–88 Hz)** as the primary sub metric. It maps almost exactly to
  Red Rocks' 25–80 Hz dB1 and is the classic building-transmission / complaint band.
  *Optional second band:* **31.5 Hz octave (~22–44 Hz)** for deep EDM sub. **Skip 125 Hz**
  for limiting (low-mid / vocal, content-dependent).
- **Window:** **1-minute Leq = the compliance / lamp number** (matches Red Rocks dB1; right
  for LF — sustained energy, not transients). **10-second = live readout.** Not 15-min (too
  sluggish), not 10s-only (too jumpy to limit on).
- **Mode:** ship in **WATCH** (display, no alarm) → log several shows across genres → set the
  limit from real data. Same data-driven path Red Rocks used.

### 5.2 Smaart side — needs Brian
- Configure an **octave-band SPL/Leq meter on the 63 Hz octave** (and 31.5 Hz if doing two),
  output over the API.
- **Capture the exact API metric label(s) Smaart streams** (e.g. `Leq 63`, `SPL 63 Oct`, or
  similar). Read them off the dashboard's **All Metrics** grid once streaming, or from the API.
  The backend keys on the literal label — see §5.3.
- If Smaart can emit a **1-minute band Leq** directly, use it (most accurate). Otherwise stream
  the band instantaneous/Slow SPL and the dashboard rolls the 60-second window (like the C track).

### 5.3 Backend (`backend/processing.py`) — mirror the existing C track
The C-weighted "bass cop" code added this session is the template. For the sub band:
- Add `self.subShort = RollingLeq(10)` and `self.subLong = RollingLeq(60)` (60s, not 360s —
  LF compliance window is 1 min).
- Add `_instant_sub(metrics)` that picks the configured band label(s) (fallbacks in order).
- Prefer a **native 1-min band Leq** if Smaart streams one; else compute `subLong` from the
  band instant.
- New `config.json` per-venue keys: `subBand` (the metric label), `subWindowSec` (60),
  `subYellow` / `subRed` (null = watch).
- New state fields (mirror the C ones): `subInstant`, `subShort`, `subLong`, `subYellow`,
  `subRed`, `subLight`, `subArmed`, `subBandLabel`, `subLongFill`.
- Lamp keys off **`subLong` (1-min) vs `subRed`**.

### 5.4 Frontend (`web/index.html`, `app.js`, `style.css`)
- Repoint the Bass Watch panel to the **1-min band Leq** (big number) + **10s band** (live),
  keep **C−A tilt** as a secondary readout. Lamp = `subLight`.
- Add a per-neighbor **sub-level estimate to the ordinance cards** (FOH band − offset).
- Bump asset `?v=` (currently 19 → 20).

### 5.5 Setting the limit (after the watch period)
- Log the **63 Hz 1-min Leq at FOH across genres** for ~several shows.
- Measure a **63 Hz-specific FOH→property-line offset** once (pink noise through the PA, or a
  show, with a handheld / second calibrated input at the Westin/Davidson boundary). **Do not
  reuse the broadband A/C offsets in `config.json` for the band** — LF propagates farther, so
  the 63 Hz offset will be smaller (less drop-off) than the broadband one.
- Set `subRed` so the worst neighbor stays under a property-line sub target. No universal
  single-octave published number exists; the closest anchors are the UK `+20 / 90 dBC`
  broadband rule and your own complaint threshold. Derive from data.

### 5.6 Calibration caveat (important)
The virtual-location offsets already in `config.json` are **broadband** A/C values. The 63 Hz
octave offset is a **different number** and must be measured separately before the property-line
sub estimate can be trusted. Until then, show the FOH band level only and label the neighbor
estimates "uncalibrated."

## 6. Gotchas / operational reference

- **n8n is containerized** (compose bridge net `n8n_default`). Any workflow HTTP node calling
  spl-monitor must use the **host LAN IP `http://192.168.200.84:8090`**, NOT `localhost:8090`
  (that resolves to the n8n container). This was the nightly-email bug. (Host→container, e.g.
  the Slack violation webhook on `localhost:5678`, is fine.)
- **The Gmail node statically requires the `pdf` attachment**, so the app now always emits a PDF
  (minimal one-page on no-data days) via `report.build_minimal_report_pdf()`.
- **n8n 2.23.4 workflow-edit recipe** (painful — follow exactly):
  - `import:workflow` **deactivates** the workflow; raw DB edits to `workflow_entity.nodes` can
    corrupt the schedule node and aren't seen as a new version; `n8n execute --id` can't run a
    Schedule-only workflow and collides on broker port 5679.
  - **Reliable sequence, as SEPARATE ssh calls** (multi-`docker compose` heredocs truncate
    output over ssh): edit JSON on Mac → `scp` → `docker compose cp` into container →
    `import:workflow` → restart n8n → `publish:workflow --id` → restart n8n → verify
    `active=true`.
  - The scheduler reads `workflow_entity` directly (no `workflow_published_version` row needed).
    Cron runs in **America/New_York**.
  - Helpers left on the VM: `/tmp/spl_inspect.sql` (state check), `/tmp/wf_fixed.json` (clean
    production workflow definition).
- **`.env` on the VM: always write ALL vars** (dropping `SPL_PORT=8090` breaks the public URL).
- spl-monitor service is unaffected by n8n restarts (separate systemd unit).
